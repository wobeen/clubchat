- 검사: `npm ci`, `npm run check`, `npm test`, `npm run test:e2e` (브라우저 설치는 구현 결과 참고)
- 진행 기록: [실행 체크포인트](ITDA_EXECUTION_CHECKPOINT.md)

## 이전 데모 설명 · 변경 전 기록

아래 내용은 이전 버전의 기록이다. 카카오톡 참고 디자인, 초안 생성 후 대화 중단, localStorage 저장 등은 현재 버전에서 변경됐다.

**방은 사라져도 일은 이어진다.**

변경된 ITDA 기획서(2026.10.25)의 회의 흐름을 구현한 독립 실행 웹 데모다. 최신 UI는 사용자가 제공한 카카오톡 화면을 참고해 **PC의 아이콘 메뉴·채팅 목록·대화창**, **안드로이드의 하단 탭·전체 화면 대화**로 각각 구성했다. 하늘색 대화 배경과 노란 내 말풍선을 사용하며, 캡슐·근거 기반 초안·공동 확정·일정 기능은 유지한다.

## PC · 안드로이드 UI

- PC: http://127.0.0.1:4173/
- 안드로이드 전용 UI: http://127.0.0.1:4173/android
- 두 디자인을 함께 보고 조작하기: http://127.0.0.1:4173/preview
- 폭 700px 이하에서는 기본 주소도 안드로이드 레이아웃으로 전환된다.

안드로이드용 **모바일 웹 UI**이며 APK가 아니다. `/android`는 PC에서 열어도 별도 모바일 레이아웃을 제공한다. 채팅 목록 → 방 열기 → 뒤로가기, 하단 탭, 터치 조작, 화면 안전 영역, 모바일 키보드 크기 변경에 대응한다. 홈 화면용 웹앱 manifest를 포함한다. 실제 서비스의 설치형 PWA에는 HTTPS 배포와 아이콘·오프라인 정책 정비가 추가로 필요하다.

### 실제 휴대폰에서 열기

PC에서 `npm run phone`을 실행하고 같은 Wi-Fi의 안드로이드 Chrome에서 실행 로그의 **Wi-Fi IPv4 주소 + `/android`**로 접속한다. 휴대폰의 `127.0.0.1`은 PC를 가리키지 않는다. 기본 포트는 4173. 실행 중인 `npm start`가 있으면 먼저 종료한다. 이 명령은 정적 데모 파일을 로컬 네트워크에 제공한다. 휴대폰과 PC의 데이터는 각 브라우저 저장소에 별도로 보관되며 기기 간 동기화는 없다. 회사·학교 Wi-Fi가 기기 간 접속을 차단하면 접근되지 않을 수 있다.

### 변경된 조작

채팅방 검색은 목록 오른쪽 돋보기, 새 회의는 새 채팅 아이콘을 사용한다. 방 안의 대화·회의록·확정 일정은 우측 상단 메뉴에서 선택하며 해당 방의 내용만 표시한다. 앱 기본 화면의 캘린더는 현재 사용자가 참여한 모든 방의 확정 일정을 모아 표시한다. 전체·안읽음·확인 필요·하위 캡슐·예약 필터가 실제 목록에 적용된다. 안읽음은 멤버별 로컬 읽음 개수로 계산하며, 방을 열면 읽은 상태로 저장된다. 참여자 전환은 **PC 왼쪽 아래 설정/프로필**, **안드로이드 하단 더보기 또는 대화방 정보 → 시연 참여자 전환**에서 한다.

미리보기 페이지의 iframe은 `designPreview=1`을 사용해 가상 데이터를 메모리에서만 편집한다. 실제 사용자가 작성한 저장 데이터에 영향을 주지 않는다. 새 샘플 대화는 최초 1회만 추가되고 기존 캡슐과 메시지는 덮어쓰지 않는다.

## 실행

Node.js 22 이상에서:

```sh
npm start
```

http://127.0.0.1:4173 접속. `npm run demo`도 같다. **npm install, 환경변수, Supabase 계정, API 키가 필요 없다.** 종료는 Ctrl+C. 다른 포트는 PowerShell에서 `$env:PORT='4174'; npm start`로 지정한다.

```sh
npm test
```

## 시연 순서

1. **소집**: 새 캡슐 만들기 → “축제 준비팀 중 2학년” 입력 → 조건에 맞는 4명 추천 → 멤버를 직접 조정하고 회의 시작. 작성자는 자동 포함된다.
2. **위임**: 기본 “축제 부스 준비 회의”의 하위 캡슐 버튼 → 넘길 메시지와 담당 멤버 선택 → 하위 캡슐 생성. 잡담은 기본 선택에서 제외된다.
3. **결론 합류**: “메뉴 가격 정하기” 열기 → 예시 대화 넣기 또는 직접 대화 → 회의록 초안 만들기 → 김민수로 확인 → 좌측 아래에서 이지은으로 전환해 확인. 두 사람이 확인하면 상위 회의에 결론 카드가 합류한다.
4. **근거 확인**: 상위 회의로 돌아와 초안 만들기 → “재료 업체 B 발주”의 담당·마감 확인 필요 확인 → 수정 아이콘으로 담당자·마감 입력 → 근거 메시지 검토. 초안을 수정하면 모든 이전 확인이 초기화된다.
5. **공동 확정**: 시연 참여자 전환으로 5명이 각각 확인. 하위 캡슐 미확정 또는 확인 필요 항목이 있으면 확정되지 않는다.
6. **다음으로 잇기**: 채팅방 우측 메뉴 → 확정 일정 → 일정 2건, .ics 다운로드, Google 캘린더 작성 링크, 다음 캡슐 예약 → 다음 캡슐에서 이전 미결 안건과 위임 결론 확인.
7. **결과 공유**: 확정 기록의 결과 카드 공유 → 텍스트 복사 또는 기기 공유. 카카오톡에는 직접 붙여넣는다.

모바일에서는 하단 더보기 또는 채팅방 정보에서 참여자를 전환할 수 있다. 새로고침 후에도 브라우저에 데이터가 유지된다. 설정의 데모 초기화로 시연을 처음부터 다시 시작할 수 있다.

## 데모 범위와 실제 연동의 구분

| 기능 | 이번 구현 |
| --- | --- |
| 캡슐·조직 멤버·문장 소집 | 가상 멤버, 팀·학년 로컬 규칙 필터, 수동 선택 |
| 대화·메시지 ID·시간 | 브라우저 저장소, 한글 조합 중 Enter 전송 방지, 검색 |
| 초대 링크 | 같은 브라우저에 저장된 캡슐 링크. 다른 기기 참여 불가 |
| 하위 위임·결론 병합 | 선택 메시지 복사, 참여자 범위 검사, 전원 확인 후 요약만 상위 전달 |
| AI 회의록 | 외부 LLM 미연결. 정해진 접두어를 인식하는 **규칙 기반 시연** |
| 검증 | 근거 ID 존재·담당자 소속·날짜 형식·일정 참여자 확인. 의미상 근거 타당성은 사람 검토 |
| 공동 확정 | 참여자별 확인, 수정 시 확인 초기화, 전원 확인 전 캘린더 반영 차단 |
| 일정·다음 회의 | 조직 캘린더, UTC .ics, Google 작성 링크, 미결·위임 결론 승계 |
| 예약 시작 | 페이지가 열려 있으면 30초마다 예정 시간 확인. 다시 접속할 때도 검사. 서버 예약 작업 미구현 |
| 알림 | 확정 시 앱 내부 알림. 푸시 미연결 |
| 카카오·인증 | SDK·로그인 미연결. 기기 공유/결과 복사, 가상 멤버 전환 |

서버 권한 경계가 없는 **로컬 시연 앱**이다. 멤버 전환은 인증이 아니며 데이터는 개발자 도구에서 접근 가능하다. 실제 민감 정보는 넣지 않는다. 저장소는 주소/브라우저별로 분리되고 동시 탭 변경은 새로고침 안내만 제공한다. 초안 추출 시 어떤 외부 API도 호출하지 않는다.

### 초안 추출 예시

일반 대화는 그대로 보관하고 다음 형식의 메시지만 초안 항목으로 추출한다.

```text
결정: 부스 위치는 B구역으로 확정
할 일: 포스터 제작 | 김민수 | 11월 3일
미결: 예산 초과분 처리 방안
일정: 부스 리허설 | 11월 12일 19:00 | 학생회관 앞 | 전원
다음 회의: 최종 점검 | 다음 주 목요일 21:00 | 온라인 | 전원
```

날짜는 메시지 작성 시각의 **Asia/Seoul** 기준이다. “내일”, “다음 주 목요일”, 명시 날짜를 지원한다. 인식하지 못한 날짜·멤버를 임의로 채우지 않는다. 실제 LLM은 이후 서버 어댑터에 연결한다.

## 파일 구조

```text
public/
  index.html       진입 문서
  app.js           화면·입력·시연 흐름
  styles.css       회의록·모달 공통 스타일
  messenger.css    카톡 형태의 PC·안드로이드 UI
  messenger-layouts.js  분리된 PC·안드로이드 화면 구조
  demo-conversations.js  보존형 샘플 대화 추가
  preview.html / preview.css / preview.js  디자인 비교 화면
  manifest.webmanifest  안드로이드 웹앱 진입 정보
  domain.js        소집·위임·추출·검증·확정·일정·내보내기
  repository.js    저장소 경계·손상 데이터 복구
  favicon.svg      새 ITDA 아이콘
tests/
  domain.test.mjs  상태 전이·권한·날짜·일정·저장 검증
server.mjs         허용된 파일만 제공하는 로컬 정적 서버
package.json       설치 의존성 없는 실행·검증 명령
IMPLEMENTATION.md  요구사항 대응·OCI 확장 계획
```

기존 Expo, Supabase, 구 배포 설정, 이전 데모, 설치 패키지·빌드 결과와 과거 기획 문서는 삭제했다. 버전 이력인 `.git`은 유지했다. 원본 PDF는 프로젝트 밖의 사용자 제공 경로에 그대로 있다.

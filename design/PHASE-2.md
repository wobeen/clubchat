# Phase 2 구현 계획

목업이 승인된 뒤에만 `app/`과 `src/`를 바꿉니다. 데이터 모델과 RLS는 이 리디자인의 범위가 아닙니다. 위키는 지금처럼 마크다운입니다.

## 1. 토큰과 테마

`src/features/ui/theme.ts`는 라이트 한 벌입니다. 안료는 종이 `#FFFFFF`, 잉크 `#1A1A1A`, 강조 `#4A4A4A`이고, 테두리와 보조 글자는 잉크를 종이에 섞은 값입니다. 색상과 다크 맵은 만들지 않습니다. 일정 화면의 옛 키(`primaryDark`, `surfaceSecondary`, `textPrimary`, `error`)는 이 세 색과 그 농도를 가리키게 남겨 호출부가 한 번에 깨지지 않게 합니다. `error`도 빨강이 아니라 잉크입니다.

웹은 `color-scheme: light`와 CSS 변수, 네이티브는 토큰 객체를 스타일에 넘깁니다. 하드코딩된 `#4A90D9`, `#417029`, `#F3F4F6`를 찾습니다. 루트 로딩 인디케이터와 로그인 화면이 여기에 해당합니다.

Pretendard는 웹에서 `expo-font` 또는 전역 CSS로 불러옵니다. 네이티브는 같은 파일을 `useFonts`로 등록합니다. 굵기 400, 500, 600, 700만 넣습니다.

## 2. 셸

순서대로 `IconRail`, `ClubListPane`, `RoomListPane`, `PaneHeader`, `panes.tsx`입니다.

- 레일 72 → 64. 동아리 마크와 사람 아바타는 강조 12% 바탕 하나입니다. `getClubColor`와 `getAvatarColor`의 다른 색은 쓰지 않습니다.
- 목록 너비 320/300 → 272.
- 활성 행은 `accentSky` 배경 대신 `accent-soft`와 왼쪽 바.
- 섹션 제목에서 이모지를 제거합니다. `w/[clubId]/index.tsx`, `w/[clubId]/[roomId].tsx`.

정보 구조는 유지합니다. 깊이 0 목록, 깊이 1 동아리 홈 안에 방 목록, 깊이 2에서 목록이 방으로 바뀌는 구조입니다.

## 3. 채팅

`MessageBubble`의 좌우 말풍선을 그룹 행으로 바꿉니다. `ChatMessageList`가 같은 발신자의 연속 메시지를 묶습니다. `ChatComposer`는 테두리 있는 한 줄, 글자가 있을 때만 보내기 버튼이 채워집니다.

수정 상태는 컴포저 위 바로, 삭제는 기존 확인 다이얼로그를 유지합니다. 길게 누르기 시트는 수정 / 복사 / 삭제입니다. `RoomDetailPane`은 같은 카드 언어로 맞춥니다.

## 4. 나머지 화면

한 묶음씩 토큰만 갈아 끼우고, 레이아웃이 목업과 다른 곳만 고칩니다.

1. 로그인, 초대 미리보기, QR.
2. 동아리 홈·방 홈의 위키와 일정 미리보기. `WikiViewer` 스타일.
3. `WikiEditor` 인라인/시트. 동작은 그대로.
4. 일정 목록·상세·폼. `scheduleUtils`의 색 참조를 토큰 별칭으로 유지한 채 값만 교체.
5. 초대, 방 관리, 동아리 관리, 멤버, 검색. `ScreenOverlay`의 너비 440/560, 반경 12.
6. 프로필 시트, 가입 코드, 만들기, 비밀번호 입장, 가입 신청.
7. 스켈레톤을 카드 형태로. `Skeleton.tsx`.

## 5. 확인

- 웹 1440과 390에서 깊이 0 → 동아리 → 방 홈 → 채팅 → 일정 상세.
- 라이트에서 본문, 강조 버튼, 보조 글자 대비. 화면에 세 안료 밖의 색이 없는지.
- 관리 오버레이가 넓은 화면에서 스택 헤더와 겹치지 않는지. 이 처리는 `_layout.tsx`에 이미 있습니다.
- 네이티브 글꼴이 없을 때의 폴백이 한글을 깨지 않는지.

테스트는 화면 테스트가 새로 생기지 않는 한 타입체크와 웹 수동 확인입니다. 이 저장소의 `package.json`에는 테스트 스크립트가 없습니다.
